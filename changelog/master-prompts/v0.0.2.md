# Dot Tank Arena Master Prompt — Prototype v0.0.2

Status: Draft Foundation Complete  
Next planned version: v0.0.3 — maps, objectives, progression economy, monetization-free cosmetics, and advanced arena events.

## Project Summary

Build Dot Tank Arena, a highly active multiplayer browser tank brawler designed around constant combat, arena control, leveling, and environmental eliminations.

The game is a true multiplayer pixel-art arena game, not an 8-bit-inspired vector prototype. Every visual element must use a consistent pixel-art style.

Architecture:

- TypeScript
- Vite client
- Socket.IO authoritative server
- Railway backend
- Sites frontend deployment

## Core Design Philosophy

Players should never feel alone. Every system should maximize encounters, combat frequency, scoreboard competition, progression, spectator excitement, and session retention. If a design choice spreads players apart or reduces interaction, prefer the alternative that increases activity.

## Multiplayer Architecture

Maintain five arena instances. Each arena supports 10 or more human players with configurable scaling.

### Matchmaking

Do not place players into the least-populated arena. Fill existing active arenas before opening new ones. Select the highest-population arena that is not full.

Example: if Arena 1 has eight players and the remaining arenas are empty, the next player joins Arena 1. Maintain approximately 8–15 active players per arena before opening another.

## Visual Direction

Everything must be pixel art. Remove smooth circles, vector-looking tanks, and minimalist placeholder graphics. Use pixel sprites, sprite sheets, pixel particles, and pixel environment tiles.

Tank sprites should use 16×16, 24×24, or 32×32 body and turret components with animation frames. Bullets should use 4×4 or 6×6 pixel sprites. Future maps should use grass, dirt, stone, ruins, walls, and hazards rendered with pixel tiles. Explosions should use 6–12 orange, yellow, and white pixel-art frames.

The UI must use `image-rendering: pixelated` and a pixel-style font such as Press Start 2P, Silkscreen, or Pixelify Sans. The leaderboard, HUD, kill feed, timers, and menus must share the aesthetic.

## Player Progression

Players gain XP from collecting dots, dealing damage, confirmed eliminations, and future objective interaction. Levels grant small capped upgrades to maximum health, movement speed, fire rate, or dash strength. Caps must prevent runaway power scaling.

## Combat

Weapons, damage, hit detection, cooldowns, and eliminations are server authoritative.

### Dash

- Desktop: Space
- Mobile: Dash button
- Quick burst
- Collision-force increase
- Cooldown
- Server authoritative

### Bump Combat

Tank collisions use momentum, speed, dash state, and level modifiers. Outcomes include knockback, displacement, and collision damage.

### Ring-Outs

The arena has a visible combat boundary such as an energy wall, lava edge, toxic waste, or void. Players outside it pass through warning, damage, and critical-damage phases. The last player who damaged or bumped a victim receives credit when the victim dies shortly after displacement. Ring-outs count as legitimate eliminations.

Players can win through aim, damage, positioning, knockback, and environmental kills.

## Bot Rework

Random movement, rotation, and shooting are not acceptable. Bots use utility-based decisions and evaluate nearby enemies, nearby XP, health, danger, positioning, edge risk, and recent attackers.

Bots navigate intentionally, rotate toward goals, pursue targets, avoid hazards, select targets by distance, health, threat, level, and spawn protection, and lead moving targets instead of firing only at current coordinates.

Personalities:

- Hunter: prioritizes eliminations.
- Collector: prioritizes XP.
- Berserker: rushes opponents.
- Sniper: maintains distance.
- Opportunist: targets weak enemies.
- Survivor: retreats when damaged.

Bots understand the arena center, edge, ring-out danger, safe repositioning, and when to dash offensively or defensively.

## Reconnect and Moderation

Maintain a 30-second reconnect grace window using session identity. Restore the same arena, stats, and progression.

Nickname validation is authoritative on the server and includes profanity filtering, leetspeak normalization, repeated-character normalization, and a safe-character whitelist. Rejected names are never stored, broadcast, or displayed.
